## 一个简单的智能体如何搭建起来的

### 工具调用

说实话智能体和LLM的差别其实就是多了一层辅助路由决策的框架罢了，你能够给他一些工具、由环境而变的提示词结构，其实就已经形成了一个最小可执行的一个智能体。

[[需要一个智能体判断工具调用和返回的一个mermaid图]]

有了这个我们就能做出一个天气预报员的小例子，你可以网上查询一些天气查询的api接口，将他封装为一个tool，然后将这个tool提供给智能体使用，让智能体调用这个tool来获取天气信息

为了让智能体能有上下文的记忆，所以我们在每一次调用接口的时候，都需要把整个聊天记录发给agent，那么同理，为了让智能体能够借助工具有感知外界信息的能力，我们自然也要回传一个tool的工具信息调用，所以在langchain的`Message`抽象类中，自然而然派生出来了 `HumanMessage` , `AIMessage` , `SystemMessage` , `ToolMessage`.

我们在调用的时候，只需要将其包装为对应的消息类型即可，比如
```python
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage, ToolMessage

messages = [
    AIMessage(content="你是一个天气播报员，专门为人们提供天气相关咨询"),
    HumanMessage(content="给我查一下扬州这边的天气最近咋样"),
]

llm.invoke(messages) # 调用llm模型，传入messages，返回结果内容

```

如何定义一个工具，其实像定义函数一样简单，AI调用这些工具，也和我们调用函数一样的思路，也是要给函数传参，然后得到对应的结果


```python
from langchain.tools import tool

@tool # 这是一个装饰器，将函数包装一层传给框架解析，因为这毕竟目前还只是一个函数（如果没有装饰器），包装后会解析函数签名，框架帮忙做进一步的工具描述的处理，参数格式的说明，让agent能更明白的使用这些工具
def get_weather(city: str) -> str:
    """查询指定城市的当前天气信息。参数 city 为城市名称，如'北京'。""" # 尽量把docstring写得清晰一些，ai也会读这些信息
    mock_data = {
        "北京": "晴，25°C，微风",
        "上海": "多云，28°C，东南风3级",
        "广州": "小雨，30°C，湿度大"
    }
    return mock_data.get(city, f"未找到{city}的天气信息")
```

AI在调用工具后可能会返回`tool_calls`（也就是说可能会产生多个工具调用），具体api参考文档【帮我找参考文献】

了解了这些，结合上面的mermaid图，自行参考相关api，完成简单的智能体搭建。


答案呼之欲出：
```python
import json
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage
from langchain.tools import tool

# 1. 定义天气工具
@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气信息。参数 city 为城市名称，如'北京'。"""
    mock_data = {
        "北京": "晴，25°C，微风",
        "上海": "多云，28°C，东南风3级",
        "广州": "小雨，30°C，湿度大"
    }
    return mock_data.get(city, f"未找到{city}的天气信息")

# 2. 将工具转换为 LLM 可理解的 Schema 格式
tools = [get_weather]

# bind_tools 会让模型知道有哪些工具可用，并约束其输出格式
llm = ChatOpenAI(model=os.getenv("MODEL_NAME"), temperature=0).bind_tools(tools)

# 构建工具名称到工具对象的映射，方便后续根据名称调用
tool_map = {t.name: t for t in tools}

# 3. 手动实现 Agent 核心循环
def run_manual_agent(user_input: str):
    # 初始化消息历史
    messages = [HumanMessage(content=user_input)]
    
    print(f"👤 User: {user_input}")
    
    while True:
        # 步骤 A: 让 LLM 决定下一步行动
        response = llm.invoke(messages)
        messages.append(response)
        
        # 步骤 B: 检查 LLM 是否要求调用工具
        # 如果 tool_calls 为空，说明 LLM 已经生成了最终回复，退出循环
        if not response.tool_calls:
            print(f"🤖 Assistant: {response.content}")
            break
            
        # 步骤 C: 执行所有请求的工具调用
        for tool_call in response.tool_calls:
            tool_name = tool_call["name"]
            tool_args = tool_call["args"]
            tool_id = tool_call["id"]
            
            print(f"🔧 Tool Call: {tool_name}({json.dumps(tool_args, ensure_ascii=False)})")
            
            # 查找并执行对应工具
            if tool_name in tool_map:
                result = tool_map[tool_name].invoke(tool_args)
            else:
                result = f"错误：未知工具 '{tool_name}'"
                
            print(f"📋 Tool Result: {result}")
            
            # 将工具执行结果作为 ToolMessage 追加到消息历史中
            # ⚠️ 注意：tool_call_id 必须与 LLM 返回的 id 严格对应
            messages.append(ToolMessage(content=str(result), tool_call_id=tool_id))
        
        # 回到 while 循环顶部，将工具结果交给 LLM 继续推理

# 4. 运行测试
if __name__ == "__main__":
    run_manual_agent("北京和上海今天天气怎么样？")
```

当然langchain提供了一个简单的库，`create_agent()`，具体api如何传入参考文档【帮我查】，上面可以精简为：
```python
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """
    查询指定城市的当前天气信息。
    Args:
        city: 城市名称，例如 "北京"、"上海"。
    Returns:
        包含该城市天气状况的字符串。
    """
    mock_weather_data = {
        "北京": "晴，气温 25°C，微风，空气质量优。",
        "上海": "多云，气温 28°C，东南风 3 级。",
        "广州": "小雨，气温 30°C，湿度较大。",
        "深圳": "阴，气温 29°C，适合室内活动。"
    }
    return mock_weather_data.get(city, f"抱歉，暂时未找到 {city} 的天气信息。")

llm = ChatOpenAI(model=os.getenv("MODEL_NAME"), temperature=0)

agent = create_agent(
    model=llm,
    tools=[get_weather],
    system_prompt="你是一个天气播报员，专门为人们提供天气相关咨询"
)

# 4. 运行 Agent
if __name__ == "__main__":
    # 模拟用户提问
    user_question = {"messages": [{"role": "user", "content": "北京今天天气怎么样？"}]}
    # 调用 agent
    result = agent.invoke(user_question)
    # 打印最终回答
    print(result['messages'][-1].content)
```





### Human in Loop

在langchain中有一个非常经典的小例子，就是一个旅店入户系统，他很好的诠释了工具调用、Human in Loop的基本的范式，如果不去特别关注代码具体的实现过程，我们也能非常轻易的大概的流程:

下面需要画一个mermaid，我的简易版：
客户入住说明 -> 意图识别，是否要工具调用? -> 调用系统内置提供的api,比如book_room(room_id)  -> 用户判断是否正确，可以选择同意与否？ -> 是，函数调用成功 -> 否，输入想要做的信息内容


在这里是不是发现有些初见端倪了？是的，做智能体其实并没有多复杂，跟传统的开发甚至可以说别无二致，只是一些业务逻辑替换为了api调用。画个流程图就能看出来。我想只是以前把代码写死了，固定死了流程。但是大模型的出现给了我们更多的机会让程序出现有趣的不一致的内容，但还是能让他能在我们的既定范式下走下去。
